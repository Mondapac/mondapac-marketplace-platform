# انتقال به Claude Code و شروع فاز ۰ — راهنمای عملی

## ۰. یک نکتهٔ مهم دربارهٔ «انتقال» قبل از هر چیز

حافظهٔ پروژهٔ این چت (که در claude.ai نگه‌داری می‌شود) و Claude Code **دو سیستم کاملاً جدا** هستند؛ چیزی به‌صورت خودکار بین‌شان منتقل نمی‌شود. آنچه واقعاً «منتقل می‌شود» **فایل‌های واقعی** این بسته‌اند — همان‌ها که Claude Code در هر جلسه از روی دیسک می‌خواند (`CLAUDE.md`, `docs/`, `.claude/agents/`). پس کار شما یک انتقال فایلی ساده است، نه اتصال دو حافظه به هم.

---

## ۱. چه چیزی در این بسته هست

```
claude-code-kit/
├── CLAUDE.md                          ← قوانین ثابت پروژه؛ Claude Code هر جلسه می‌خواند
├── PLAYBOOK-fa.md                     ← نقشهٔ راه فازبندی‌شدهٔ کامل ساخت
├── TEAM-PLAYBOOK-fa.md                ← نحوهٔ هماهنگی ۱۱ عامل تخصصی
├── .claude/agents/                    ← ۱۱ Subagent (cto, product-owner, architect, ...)
├── docs/spec/technical-spec.md        ← سند فنی اصلی نسخهٔ ۲.۰
├── docs/features/00..09.md            ← سند قابلیت‌ها (SEL, CAT, CERT, INTL, ...)
├── docs/architecture/*.md             ← سه سند معماری (Vertical, Market, راه‌اندازی Branch)
└── docs/adr/0001..0003.md             ← سه ADR آمادهٔ بازبینی (وضعیت: Proposed)
```

این دقیقاً ساختار ریشهٔ یک ریپوی واقعی است — کپی مستقیم است، نه چیدمان دستی فایل‌به‌فایل.

---

## ۲. مراحل انتقال

```bash
# ۱) یک ریپوی خالی بسازید و کلون کنید
git clone <آدرس ریپوی خالی شما> mondapac-marketplace
cd mondapac-marketplace

# ۲) کل محتوای claude-code-kit را داخل ریشهٔ ریپو کپی کنید
#    (فایل‌هایی که از این چت دانلود کرده‌اید)
cp -r /مسیر/دانلود/claude-code-kit/. .

# ۳) اولین commit — این خط شروع تاریخچهٔ پروژه است
git add .
git commit -m "chore: bootstrap project docs, ADRs, and Claude Code team"
git push

# ۴) اجرای Claude Code در ریشهٔ همین ریپو
claude
```

**تأیید نصب صحیح** (داخل جلسهٔ Claude Code، قبل از هر کار دیگر):
1. دستور `/agents` را بزنید — باید ۱۱ نقش (cto، product-owner، software-architect، ...) را فهرست کند.
2. یک پیام ساده بفرستید: «طبق CLAUDE.md، این پروژه چیست و کدام ADR ها منتظر تأیید هستند؟» — اگر Claude Code درست پاسخ داد (نام MondaPac، سه ADR با وضعیت Proposed)، یعنی همه‌چیز درست خوانده شده.

## ۳. اولین کار واقعی در فاز ۰: تأیید یا اصلاح سه ADR

سه ADR (`docs/adr/0001` تا `0003`) با وضعیت **Proposed** نوشته شده‌اند — یعنی پیش‌نویس‌اند، نه تصمیم نهایی. قبل از اسکلت‌سازی پروژه، باید این‌ها را عبور دهید. این اولین‌جایی است که تیم Subagent واقعاً وارد عمل می‌شود:

```
از عامل cto بخواه هر سه ADR در docs/adr/ را بازبینی کند، وضعیت هرکدام را از
Proposed به Accepted تغییر دهد (یا در صورت مخالفت، دلیل و پیشنهاد اصلاح بدهد)،
و مشخص کند کدام تصمیم‌ها (اگر هست) قبل از شروع فاز ۰ نیاز به ورودی من (مالک
پروژه) دارند.
```

بعد از این تأیید، اولین ADR واقعی خودتان را هم لازم دارید — تصمیم Stack دقیق (ORM: Prisma یا TypeORM؛ Message Broker adapter؛ مدل پول/GST) که در `CLAUDE.md` به‌عنوان `ADR-0004` رزرو شده:

```
از عامل software-architect بخواه با خواندن docs/spec/technical-spec.md و
docs/architecture/*.md، پیش‌نویس ADR-0004 (تصمیم ORM و ساختار adapter برای
Message Broker) را آماده کند. سپس از عامل cto بخواه آن را تأیید کند.
```

## ۵. الگوی کار روزمره از این به بعد (یادآوری از TEAM-PLAYBOOK-fa.md)

هیچ‌وقت مستقیم به `backend-developer` یا `frontend-developer` نگویید «این قابلیت را بساز». مسیر درست:

```
product-owner (Story از docs/features/*.md)
   → software-architect (طراحی، فقط اگر غیرتریویال)
   → backend-developer / frontend-developer (پیاده‌سازی)
   → qa-engineer (تست مستقل)
   → security-tester (فقط حوزه‌های حساس: هویت، پرداخت، CERT-*)
   → qc-release-manager (دروازهٔ نهایی)
```

جزئیات کامل و نمونه پرامپت در `TEAM-PLAYBOOK-fa.md`.

## ۶. نکته دربارهٔ اکانت Claude Code Max

پلن Max سقف مصرف بالاتری می‌دهد — از آن برای دو مورد استفاده کنید:
- **موازی‌کاری واقعی:** با Git Worktree، دو جلسهٔ Claude Code هم‌زمان روی دو Story مستقل (مثلاً بک‌اند گواهی + فرانت پنل فروشنده) کار کنند.
- **استفادهٔ آزادانه از عامل‌های Opus-محور:** چهار عامل حساس (`cto`, `software-architect`, `backend-developer`, `security-tester`) در همین بسته از ابتدا روی مدل `opus` تنظیم شده‌اند (بازبینی‌های معماری/امنیت ارزش هزینهٔ مدل قوی‌تر را دارد)؛ دیگر لازم نیست برای صرفه‌جویی از فراخوانی‌شان خودداری کنید.

برای جزئیات دقیق پلن (سقف‌ها، مدل‌های در دسترس)، مستندات رسمی به‌روزتر از این سند است: https://docs.claude.com
