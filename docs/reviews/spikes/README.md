# Spike scripts (evidence, not product code)

The scripts behind the reports in `docs/reviews/`. They are kept so Hassan and later slices can
re-run each measurement (ADR-0029 spike conditions; Hassan C11). Nothing here is imported by the
application, built, linted or shipped; the dummy credentials are the throwaway keys of a local
SeaweedFS started by hand. Each folder is run on its own (`npm install` inside it). Sample
files are generated by `samples.mjs`, not committed.

| Folder | Report | Needs |
|---|---|---|
| `adr-0029-spike-1/` | `adr-0029-spike-1-storage.md` | SeaweedFS S3 on 127.0.0.1:8333, identities `provkey`, `apikey`, `originkey` |
| `adr-0029-spike-2/` | `adr-0029-spike-2-intake.md` | Node with sharp, `bwrap`, `qpdf`, Poppler, `clamd` |
| `sellers-s1-s3/` | `sellers-spikes-s1-s3.md` | PostgreSQL, the repository's `prisma/schema` copied beside `s2.sql` |

Re-runs belong on the digest-pinned image and the real worker image (the reports' conditions),
and each measured property becomes a CI test in the slice that needs it.
